# 카드뉴스 만들기 (/make-cards)

인자: 제품명 또는 find-items 후보 번호, (선택) 사진/영상 URL·릴스 shortcode, (선택) 형식 `릴스` / `캐러셀`.

**형식 정하기** (spec.json의 `"format": "carousel" | "reel"`):
- 인자에 `릴스`/`캐러셀`이 있으면 그대로.
- 없으면 A/B 테스트 중이므로 `tools/howabouthis/history.json`의 마지막 게시 형식과 **반대**로 제안한다 (기록 없으면 릴스). 사용자가 바꾸면 따른다.
- 테스트 비교: 게시 48시간 후 비팔로워 도달·공유·저장·팔로우 (CLAUDE.md 참고).

## 0. 준비
`bash tools/howabouthis/setup.sh` (폰트·Pillow). 작업 폴더: `work/cards/<id>/` — `id` = `YYYY-MM-DD-<영문슬러그>` (예: `2026-10-05-dish-rack`).

## 1. 사진 확보 → `work/cards/<id>/img/`
우선순위:
1. 사용자가 준 사진/영상 (URL 또는 업로드 파일): `prep.py images <폴더> <url…>` / `prep.py video <폴더> <url>`
   - 사용자가 **제미나이로 만든 사진**을 주면 같은 방식으로 받고, [gemini-guide.md](gemini-guide.md) 3)으로 검수한다
     (원본과 제품 색·로고·모양이 다르면 쓰지 않는다). 캡션 끝에 `일부 이미지는 AI로 편집했어요.` 를 넣는다.
   - **사용자가 후보 번호를 고르면("2번") 먼저 제미나이 캐러셀 프롬프트를 만들어 주고 멈춘다** (사진이 오면 이어서 진행):
     1. 제품 실물 정보 확인 (공식몰·무신사: 정확한 제품명·품번·컬러·디테일). 확인 못 한 디테일은 프롬프트에 쓰지 않고 "원본 그대로"로.
     2. gemini-guide.md의 "레퍼런스 스타일"을 이 제품에 적용 — **장면은 제품 중심으로: 제품 단독 3 + 바짝 크롭 착용 2, 사람·전신 중심 컷은 0~1** (2026-10-05 사용자 결정). 같은 카테고리 상위 게시물을 새로 봐야 하면
        `business_discovery`의 `children{media_url}`로 계정당 1회만 받는다 (공개 embed 페이지는 2026-10 기준 이미지가 안 나옴).
     3. 모든 프롬프트 **첫 줄에 비율을 쓴다**: `비율 4:5 세로(1080x1350)` (2026-10-05 사용자 요청 — 도구 화면 설정과 별개로 프롬프트에도).
        도구가 한 장씩 만드는 방식(드롭샷 등)이면 장면별 독립 프롬프트로, 대화형(제미나이)이면
        채팅에: **한 번에 붙여넣는 통합 프롬프트 1개** — 사용자는 사진을 순서 없이 섞어 올린다. 사진 목록·순서 안내는 넣지 않고,
        "각 장에 맞는 사진을 네가 골라 써"를 프롬프트에 넣는다. 거울·착용 컷엔 gemini-guide.md "사람이 찍은 느낌"을 반영한 자세·구도를 구체적으로 쓴다.
        프롬프트를 주기 전에 **gemini-guide.md "제품 구조로 동작·상태 검증"을 한 줄씩 돌린다** (립 밑단이 바람에 날림 같은 불가능한 묘사 금지).
        **[korean-style.md](korean-style.md)를 먼저 읽고** (갱신 날짜가 지난 시즌이면 웹 검색으로 갱신부터), **gemini-guide.md "한국 스타일"을 반드시 넣는다** — 헤어·코디를 원본에서 따라하지 말라는 문장, 한국 20대 헤어(시리즈 하나로 고정)·코디·배경을 장마다 구체적으로
        (기본 규칙 + 장면 5개(표지 → 본문 3 → 마무리, 레퍼런스 상위 게시물이 모두 5장)를 각각 따로 된 이미지로 순서대로 생성) + 이어 만들기·수정 한 줄 요청.
        장면별 개별 프롬프트는 `work/gemini/<id>.md`에 예비로 저장.
     4. 카드 문구(말풍선 카피)는 사진이 온 뒤 2단계에서 쓴다.
2. 내 계정 릴스 장면: `prep.py own-reel <폴더> --shortcode <코드>` (저작권 음원 릴스는 원본을 못 받음)
3. 쿠팡 상품 이미지 (`market.py coupang` 결과의 이미지 URL, 키 있을 때) — 단색 배경 제품컷이라 1~2장만
4. 제조사·브랜드 공식 이미지 — 출처 확인
- ❌ 레퍼런스 계정(un_ni_item, ssokssok.daily 등)·타인 SNS 사진은 쓰지 않는다.
- 사진이 부족하면(최소 4장) 사용자에게 요청하고 멈춘다.

`prep.py`가 만든 `sheet.jpg`를 Read로 보고 컷을 고른다: 표지 1 + 본문 3~6 + CTA 1 (총 5~8장 권장, 최대 10).
- **사진은 그 장 문구가 말하는 걸 보여주는 컷으로 배치한다 (2026-10-05 사용자 결정)**:
  제품 단독컷(옷걸이·접사·플랫레이)은 맥락·소재·디테일 장과 마지막 장에, 바짝 크롭 착용 컷은 표지·활용 장에. 사람·전신 중심 컷은 0~1장.
  카피를 먼저 정하고 장마다 맞는 사진을 다시 고른다 — 제미나이가 준 순서를 그대로 쓰지 않는다.
- 제품이 화면을 꽉 채워 말풍선 자리가 없으면 `{"src": ..., "zoom": 0.85~0.9, "pos": "50% 100%"}` (축소하면 여백은 같은 사진을 흐리게 채움).
- 영상 프레임에 **자막·워터마크가 박혀 있으면** `prep.py crop`으로 피해서 자르거나, 말풍선 위치(`bubble: top|bottom`)로 가린다.
- 4:5 비율로 자동 크롭(cover)되므로 초점은 `{"src": "...", "pos": "50% 30%"}` 로 조정.

## 2. 카피·spec 작성 → `work/cards/<id>/spec.json`
형식은 `tools/howabouthis/examples/sujeo/spec.json` 그대로. 카피 규칙은 [copy-guide.md](copy-guide.md) 를 **반드시** 읽고 따른다.

## 3. 렌더 & 자체 검수
`python3 tools/howabouthis/cards.py work/cards/<id>/spec.json` → `out/NN.jpg`, `preview.jpg`
- `preview.jpg`와 표지(`out/01.jpg`)를 Read로 직접 확인:
  - 글자 잘림·과도한 축소(자동 축소 후 너무 작으면 문구를 줄인다)
  - **제품은 어느 부분도 말풍선·글자로 가리지 않는다 (기본 중의 기본, 2026-10-05 사용자 지적)** — `out/` 모든 장을 한 장씩 보고 확인.
    가리면 `bubble` 위치(top/bottom)를 바꾸고, 그래도 겹치면 `pos`·`zoom`으로 제품을 옮긴다. 제품이 아닌 것(마음에 안 드는 하의 등)은 말풍선으로 가려도 된다.
    **사람 얼굴이 보이면 말풍선으로 가린다 (2026-10-05 사용자 결정)** — `bubble`을 얼굴 쪽에 두고 `pos`·`zoom`으로 얼굴을 말풍선 밑으로 옮긴다.
    눈 정도는 보여도 된다(폰으로 코·입을 가린 거울샷 등). **AI가 사진에 박아 넣은 깨진 글자도 말풍선으로 가리고 쓴다** — 사진을 버리지 않는다.
    위·아래로 안 맞으면 슬라이드에 `"bubble_top": <윗변 y px>`, `"bubble_width": <최소 폭 px>`로 정확히 맞춘다 (제품은 여전히 가리지 않게).
    얼굴 바로 아래가 제품(카라 등)이면 제품이 최대한 안 가려지는 위치로 맞추고, 겹친 게 있으면 사용자에게 말한다.
    예외: 마지막 장(CTA)은 사진 전체를 어둡게 깔고 가운데에 글자·입력창을 얹는 원래 디자인을 쓴다 (사용자 허용, 2026-10-05).
  - 사진이 너무 흐리거나 어두우면 교체
- 문제 있으면 고쳐서 다시 렌더.

## 3-2. 릴스 (format이 reel일 때)
`python3 tools/howabouthis/reel.py work/cards/<id>/spec.json` → `reel.mp4`(1080x1920, 표지 3초·본문 2.5초·크로스페이드), `reel_preview.jpg`
- `reel_preview.jpg`를 Read로 확인: 카드가 화면 위쪽에 있고 아래 440px는 비어 있어야 함(릴스 하단 UI 영역).
- 배경은 각 장의 원본 사진을 흐리게 깐 것 — spec의 이미지 순서(표지, 본문, CTA)가 out/NN.jpg와 같아야 한다.
- 음원은 저작권 없는 파일만 `--audio`로. 인스타 음악은 API로 못 붙임 → 필요하면 게시 후 앱에서 추가하도록 안내.

## 4. 사용자 검토
- SendUserFile로 `preview.jpg` (+ 표지 원본) 전송. 릴스면 `reel.mp4`와 `reel_preview.jpg`도.
- 캡션 전문을 채팅에 보여준다.
- "이대로 올릴까요? 고칠 곳 있으면 말씀해주세요"라고 묻고 **멈춘다**. 수정 요청은 반영해서 다시 미리보기.
- 승인("올려", "게시해" 등)이 오면 `post-cards` 스킬로 진행.
